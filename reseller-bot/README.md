# بات فروش پنل نمایندگی سنایی

بات از رابط تلگرامی Velora استفاده می‌کند. کیف پول، شارژ دستی، دکمه‌های شیشه‌ای و منوی ادمین در دسترس‌اند. پرداخت پنل از موجودی انجام می‌شود. کوپن تخفیف و پاداش خودکار ارجاع برای خرید پنل غیرفعال‌اند.

۱. فورک 3x-ui-aether همین شاخه را روی سرور پنل اجرا کنید. در محیط سرویس پنل یک توکن تصادفی مستقل حداقل ۳۲ کاراکتری با نام `XUI_DELEGATED_SALES_TOKEN` قرار دهید. پنل را از طریق HTTPS ارائه کنید.
۲. در بخش Admins سنایی گروهی مانند `forosh` بسازید و اینباندهای فروش را به آن اختصاص دهید.
۳. روی سرور بات، در پوشهٔ `reseller-bot`، وابستگی‌ها را با `python -m pip install -r requirements.txt` نصب کنید. متغیرهای محیطی زیر را در سرویس تعریف کنید و `python bot.py` را اجرا کنید. بات فایل `.env` را خودش نمی‌خواند.

| متغیر | مقدار |
|---|---|
| `BOT_TOKEN` | توکن تلگرام برای این پردازه |
| `SUPER_ADMIN_ID` | آیدی عددی مالک و مقصد خصوصی مشخصات سفارش |
| `SANAEI_URL` | آدرس HTTPS سنایی شامل مسیر پایهٔ پنل |
| `SANAEI_SALES_TOKEN` | همان توکن اختصاصی فروش سنایی |
| `RESELLER_FERNET_KEY` | خروجی دستور `python -c 'from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())'` |
| `BOT_DATA_DIR` | مسیر اختیاری دادهٔ پایدار و خصوصی بات |
| `BANK_CARD_NUMBER`، `BANK_CARD_HOLDER`، `BANK_NAME` | اطلاعات اختیاری شارژ دستی |
| `SUPPORT_USERNAME`، `LOG_CHAT_ID` | مقصدهای اختیاری پشتیبانی و لاگ |

برای انتقال دادهٔ قبلی از یک کپی دایرکتوری داده به‌عنوان `BOT_DATA_DIR` استفاده کنید. در مهاجرت، پیش از اجرا پردازهٔ قبلی را متوقف کنید. توکن‌ها و کلید رمزگذاری را فقط در محیط سرویس نگه دارید و از کلید و داده‌ها جداگانه بکاپ بگیرید.

## جریان فروش

- در **پنل ادمین ← پلن‌های نمایندگی ← گروه فروش** گروه `forosh` را انتخاب کنید. سپس از **افزودن پلن** ورودی `نمایندگی ۱۵۰ | ۱۵۰ | ۵۰۰۰۰۰` را بفرستید. قیمت صفر پلن را از فروش خارج می‌کند.
- خریدار در **خرید پنل نمایندگی** پلن و قیمت را می‌بیند و پرداخت از کیف پول را تأیید می‌کند. بات کسر موجودی و سفارش را یکجا ثبت می‌کند. سنایی با شناسهٔ پایدار سفارش یک نماینده می‌سازد. رمز اولیه و لینک ورود در چت خصوصی برای خریدار و مالک فرستاده می‌شود و از **پنل‌های من** قابل مشاهده است.
- اگر نتیجهٔ API مشخص نباشد، بات سفارش را پس از راه‌اندازی مجدد هم پیگیری می‌کند. در صورت رد قطعی پلن یا گروه، مبلغ یک‌بار به کیف پول برمی‌گردد.
- در **گزارش نماینده‌ها** سقف و مصرف نمایندگان را ببینید. برای افزودن ۵۰ گیگ به نمایندهٔ ۲۱ با سقف فعلی ۱۵۰، در **تغییر حجم** مقدار `21 | 150 | +50` را بفرستید. اگر سقف از زمان گزارش تغییر کرده باشد، درخواست رد می‌شود. کاهش سقف زیر مصرف می‌تواند ترافیک نماینده را متوقف کند.

## دسترسی و تست

توکن بات فقط برای API فروش است. مسیر نماینده از حساب، کوکی و مسیرهای مستر جداست. در استقرار اینترنتی، دسترسی به مسیر `/delegate-sales/v1/` را در صورت امکان به IP سرور بات و مسیر مستر را به شبکهٔ مدیریت محدود کنید. لاگ وب‌سرور نباید هدر Authorization یا بدنهٔ سفارش را ذخیره کند.

GitHub Actions تست‌های بات و نمایندگی فورک را اجرا می‌کند. برای تست استقرار واقعی به پنل آزمایشی HTTPS و توکن‌های مخصوص تست نیاز دارید.
